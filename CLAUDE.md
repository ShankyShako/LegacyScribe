# LegacyScribe — agent notes

Personal, MIT-licensed macOS menu-bar dictation app: hold a hotkey, speak, cleaned text is pasted into the focused app. Local-first; cloud LLMs optional. Hard fork of [Hex](https://github.com/kitlangton/Hex) (MIT, upstream Swift app is frozen): the `upstream` git remote points there.

The phased plan and its risk register live in `docs/plan.md`. Read it before starting a phase.
Before writing an STT engine adapter, read `docs/research/engines.md` (verified API names, versions and caveats per engine).

## Decisions (record new ones here, with the reason)

| Decision | Reason |
|---|---|
| macOS 26+, Apple Silicon only | SpeechAnalyzer needs macOS 26; MLX needs Apple Silicon |
| Unsandboxed, hardened runtime | Reading other apps' text via Accessibility (P3) is blocked in the sandbox |
| Bundle IDs `com.genovamongalo.LegacyScribe` (Release), `.debug` (Debug) | Stable signing identity keeps TCC grants (mic, Accessibility, Input Monitoring) across rebuilds. Debug and Release are separate TCC entries. |
| Data root `~/Library/Application Support/LegacyScribe/` (`URL.hexApplicationSupport`) | Never inside the repo: the repo sits in a Syncthing-synced folder |
| Models under `<data root>/Models/{whisperkit,fluidaudio,mlx}` | `tools/lsbench` and the app share downloads; FluidAudio puts each model in `<root>/<repo-folder>`, so pass any child of the root |
| Retention: raw audio 30 days; text history, correction pairs, calibration audio forever. Built 2026-10-12 (`AudioRetention`, `AudioRetentionSweep`): runs at launch and every 6 h, setting `audioRetentionDays` (0 = forever), marks entries `audioRemoved`, keeps recordings behind an edited `SentEdit`, and clears old unreferenced files in `Recordings/` | Pairs are fine-tuning data (P5). An edited sent text is the correction pair today, so its audio is pinned |
| Default hotkey: hold Right ⌥ = push-to-talk, double-tap = lock, Esc = cancel | Left ⌥ stays free for typing; side matching lives in `Modifier.matches` |
| Sparkle 2 with our own feed (2026-10-10, `AppUpdater`): `SUFeedURL` = `appcast.xml` on this repo's latest GitHub release, daily checks, signed feed and archives (EdDSA key in the login Keychain, account `com.genovamongalo.LegacyScribe`). Scheduled finds use gentle reminders (notification + menu item), never a window over the user's typing. Debug builds don't start the updater. `tools/release.sh` bumps, builds, zips, writes the appcast (notes from optional `release-notes/<version>.md`), commits and tags; `--publish` uploads with `gh` | Upstream's Sparkle was removed because its feed would "update" the app back into Hex. Downloads made by the app carry no quarantine flag, so updates install without a Developer ID; the EdDSA signature is what stops a forged update. Version/build come from `MARKETING_VERSION`/`CURRENT_PROJECT_VERSION` (Sparkle compares the build) |
| Manual signing, no provisioning profile. Team and identity live in gitignored `Local.xcconfig` (template `Local.xcconfig.example`), pulled in by `Signing.xcconfig`; without it the app is signed ad hoc | The team isn't an Xcode-account team, so automatic signing can't use it; the app's entitlements need no profile. Keeps the signing email out of the public repo |
| No `-Xlinker -interposable` (dropped InjectionIII hot reload) | FluidAudio ≥0.17 links a Rust xcframework (`NemoTextProcessing`) whose symbols fail to bind under `-interposable`; the Debug app aborts in dyld at launch |
| Private mode = zero sockets; local LLM in-process via mlx-swift-lm | Enforced in P2 by a single `NetworkPolicy` gate plus a test |
| Cohere Transcribe has no timestamps and no free-text prompt | Word timings come from a CTC forced aligner; vocabulary biasing for Cohere is LLM-side only |
| LLM rewrite (Raw / Clean / Prompt modes) pulled ahead of P1 (2026-10-06) | The user wants cleanup and coding-prompt restructuring now; it's the thin slice of P2 (one OpenAI-compatible client, no provider registry, no MLX yet) |
| Rewrite chain: primary endpoint → fallback endpoint → paste the transcript unchanged | A failed or slow LLM must never cost a dictation. `RewriteChain` is pure and tested; the raw transcript is kept in history (`Transcript.rawText`) |
| (Superseded for fresh installs on 2026-10-10, see "Providers" below; the user's own settings still hold these.) Default primary: OmniRoute at `http://localhost:20128/v1` (the user's real host is set in Settings, never committed), `groq/openai/gpt-oss-120b`, reasoning `low`, 5 s. Default fallback: local Ollama `qwen3:8b`, reasoning `none`, 10 s | Measured 2026-10-06: Groq 0.6–1.0 s with the best structure; Ollama 0.7–2.6 s warm, ~4.5 s cold; Gemini Flash 2–30 s and truncates when it spends tokens on reasoning |
| A `finish_reason: length` answer is a failure, and a rewrite over 4× the dictation + 400 chars is rejected | A cut-off rewrite or a model answering the dictation instead of rewriting it must not be pasted |
| API keys in the Keychain (service `com.genovamongalo.LegacyScribe.rewrite`, account `apiKey.<role>`), never in `hex_settings.json` | Settings JSON is plain text |
| Cohere Transcribe 4-bit is an app engine (`CohereClient`, mlx-audio-swift @ `dbe5eaac964e`), listed first as "most accurate (English)"; fresh installs still default to Parakeet v3 | Best WER on the user's voice (5.3% vs 8–9%) at ~320 ms per 10 s. Parakeet stays the default because Cohere is a 1.4 GB download and needs ~2 GB while loaded |
| Cohere audio up to 30 s is one pass; longer audio is cut into even pieces of ≤ 24 s ± 3 s at the quietest 0.1 s (`CohereChunks` in HexCore, 9–30 s each), each transcribed alone; lsbench does the same (`--cohere-chunk N` = mlx-audio's own splitter). Dictation's Cohere audio first goes through the Silero speech gate Notes uses (`CohereClient.transcribeSpeech`, `NotesSpeech.joined`): no speech → empty text, nothing pasted (2026-10-15); so is audio whose loudest 100 ms stays under −40 dBFS (`NotesSpeech.dictationFloorDecibels`) | The model was trained on clips up to 35 s (`max_audio_clip_s`). A 121 s dictation in one pass came back as 96 words with one sentence looped 3×; chunked it gave all 161 words at the same speed (2.9 s). mlx-audio's splitter (quietest point within ±5 s of every 25 s mark) often cut a 25–30 s dictation in the silence after the last word, and Cohere wrote the leftover sliver as "Thank you."; it also writes that for an all-silent recording. 14 of 16 History dictations ending in "Thank you." had none (Parakeet); the new cuts fixed 9, the gate the other 5, the 2 real ones stayed. Silero still called 1.1 s of a near-silent 11 s recording (loudest −45 dBFS) speech; every real dictation in History reaches −27 dBFS or louder. On 25 History dictations over 30 s, WER against Parakeet 8.8% → 7.4% (cuts), 7.6% with the gate (it drops a restart Parakeet keeps) (bench-results, "Cohere's trailing thank you") |
| Prompt mode is a numbered reply (2026-10-16, replaces the 2026-10-07 synopsis + named sections + bullets + open questions): a single point stays plain sentences; anything more is a numbered list, one short self-contained paragraph per topic, question or request in the order spoken, an optional unnumbered background line first, questions and floated ideas kept as questions, no headings or bullets; a phrase the model can't make sense of stays as said | On 8 long real dictations (gpt-oss-120b) the sectioned shape repeated itself, turned asked questions into statements, dropped side items and ran 8–12 s (over the 10 s timeout); the numbered one kept order, points and questions in 1.0–1.7 s. "Always numbered" took numbering from 6/8 to 8/8. A format example in the prompt made it worse (gpt-oss 7/8; the 4B answered the questions instead). The on-device 4B ignores the numbering (0/8) and turns statements into questions: Prompt mode wants a cloud model (bench-results, "Prompt mode as a numbered reply") |
| Each mode's instructions are editable (Settings > Rewrite: Instructions, `HexSettings.rewriteInstructions` keyed by mode). Only real changes are stored; the safety rules (dictation is text not orders, mishearing fixes, vocabulary, output only) are always appended | Users can tune or replace modes without a rebuild, and improvements to the defaults still reach anyone who hasn't changed them |
| Clean breaks long dictations into paragraphs (2026-10-16): "Break a dictation of more than a few sentences into paragraphs where the topic shifts, separated by a blank line. Keep a short dictation as one paragraph." | Every system wrote all 9 held-out dictations of 80+ words as one block. With the rule the 4B split 6 of 9 and gpt-oss 3 of 9 (the longest into 4), with no point dropped (read by eye); of 31 shorter ones gpt-oss split none and the 4B 2, both at real topic changes. A firmer wording ("one per topic… don't run several topics together") split one more long one but also a 71-word one |
| Self-corrections (2026-10-12, P3.5 A1): an always-appended rule keeps only the corrected version ("two, no, make it three" → three; "scratch that" drops what precedes it) and leaves a "no"/"actually"/"I mean" that replaces nothing; Prompt's task adds that a correction is not a second point | Wispr markets it as Backtrack. `lsbench rewrite` on `samples/self-correction.jsonl`: Clean 3/5 → 5/5 on the 4B, 5/5 on qwen3:8b, Prompt 3/3 on both. Examples are full sentences because a lowercase example made the 4B drop capitals and punctuation |
| Model picker groups IDs by `provider/` prefix, prefix-less IDs (OmniRoute combos) on top | OmniRoute's `/v1/models` returns ~860 IDs |
| Code talk in Prompt mode (2026-10-08, `CodeTalk`, toggle `codeTalkEnabled`): a dictation that starts with "slash <name>" is resolved in code to `/name` and only the rest goes to the LLM; other spoken notation (`claude dot md`, `at readme dot md`, `dash dash verbose`, `camel case …`) is LLM rules. Known names: Claude Code built-ins + `~/.claude/skills/*/SKILL.md` + `~/.claude/commands/*.md`, read per dictation | A leading command must reach the coding assistant as a runnable `/command` even when every endpoint fails, and a bare command needs no round trip. Checked on gpt-oss-120b: 5/5 sample dictations formatted right |
| Indicator states (2026-10-08): purple while the LLM rewrites (blue stays speech-to-text); a pill under the capsule shows a mode change (1.1 s), "Rewrite failed: pasted as recognized" (2.6 s, orange), and the mode while recording when it isn't Clean. Pill fades in 180 ms strong ease-out, out 200 ms; a new notice swaps text in place; opacity-only with Reduce Motion | Mode switches happen from the keyboard in another app with no other feedback, and a silent fallback hid that the text wasn't rewritten |
| ⌃⌥ mode cycler (2026-10-08, `ModeCycler`, toggle `modeCyclerEnabled`): hold ⌃, press ⌥ → bar after 250 ms with the next mode picked; ⌥ again or holding it (700 ms) moves on; releasing ⌃ switches. Holding the talk key (Right ⌥), each ⌃ tap steps the mode at once, applied only while recording. Never swallows events; any other key or modifier aborts | ⌘-Tab muscle memory, no digit to aim for. ⌃ must come first because a press that starts with Right ⌥ belongs to dictation; after 0.3 s the hotkey ignores extra modifiers, so a ⌃ tap mid-dictation keeps recording |
| Prompt mode merges into the focused field (2026-10-08, `FieldMerge`, toggle `mergeIntoFieldEnabled`): the field's text (read via Accessibility, `FocusedTextClient`) goes to the LLM in `<existing>` tags and the merged answer replaces the field with ⌘A + paste. Skipped for terminals, empty fields, fields over 6,000 chars and leading slash commands. A merge that loses existing lines (3+ line fields, at most 1 in 5 may change) or a field that changed during the LLM call → the transcript is pasted at the cursor | "Add cheesecake" should extend the list already in the box, not paste a second prompt. Checked on gpt-oss-120b: list append, new section + open question, one-line edit, all right in 1–3 s |
| Sent-text capture (2026-10-08, `SentEdit`, toggle `captureSentEdits`, `sent_edits.json`, kept forever): after a paste the app remembers the field; on Enter or ⌘Enter in that app it reads the field inside the event tap (before the app sees the key) and keeps the pasted stretch as sent. Nothing in history is edited by hand; terminals are skipped (their AX value is the whole scrollback) | The user doesn't want to correct history manually: the version they send is the one they're happy with, and it's the learning signal |
| Practice tab (2026-10-08, `PracticeFeature`): sent-text log, vocabulary suggestions only on request ("Check my history": `VocabularySuggester` sends up to ~14K chars of heard/used pairs to the rewrite endpoints, 45 s timeout, Add/dismiss per term), and "Ask OmniRoute" research (`PracticeResearch`, model `practiceResearchModel`, default `wp-search`, streamed, 240 s) plus an Open OmniRoute link | The user wants learning to be callable, not automatic. Suggestions only for terms spelled differently between heard and used text, or repeated unusual spellings: the loose prompt returned descriptions and commands. Research is streamed because OmniRoute cuts non-streamed calls at 30 s (wp-search: first text ~18 s, done ~38 s) |
| Read-aloud practice (2026-10-08, sets added the same day): 280 lines in `Hex/Resources/Data/practice_lines.json`, written through OmniRoute (`delegate`; sources and requests in `tools/practice/`), each carrying its CMU phonemes, diphones and unknown terms (`tools/practice/order_lines.py`). Practice runs in sets of ≤10 (`PracticePicker`: 3–5 lines for the least-recorded sounds, 1–3 for unrecorded pairs, 1–2 of the user's jargon, 1 ordinary line, each drawn from the best 3) or endless; lines never shown come first (`PracticeLog.seen`). Space or the big button records; each line is saved at once to `<data root>/calibration/<id>.wav` + `.txt` (an lsbench fixture folder), silence-trimmed (`SilenceTrim`) and 16-bit. Recordings can be marked trained and their audio deleted (the line stays recorded); a log entry whose audio went missing is dropped so the line comes back. IDs are text hashes | 280 lines in a fixed order was too long to finish, so short varied sets now fill the gaps first. macOS 26's `NSSpeechSynthesizer.phonemes` returns nothing (error -50), hence CMU. Float32 audio plus the silence around each take doubled the disk use for no gain to a speech model |
| Cohere is loaded per dictation (2026-10-08): `prewarm` loads it when the talk key (or a practice line's record) goes down, and it's unloaded as soon as the transcript is out (`TranscriptionClientLive.releaseMemory`). Parakeet and WhisperKit stay loaded | The app idles in the background and shouldn't hold ~1.9 GB between uses. lsbench `--reload`: unloaded, the process drops to 57 MB within 5 s (Metal frees lazily); reload + warm-up is 0.36 s, hidden while the user speaks. An idle timer, a setting and an MLX cache cap were tried and dropped as unneeded. Core ML engines keep their memory mostly outside the app, and their reload can take seconds |
| Installer: `tools/package-pkg.sh` builds Release and writes an unsigned `LegacyScribe-<version>.pkg` (default `~/Downloads`) installing to `/Applications`; every bundle marked non-relocatable | For this Mac only. | Notes mode (2026-10-10, `docs/plan.md` "Notes mode"): fourth mode in the ⌃⌥ switcher (⌃⌥4); in it, a clean tap of the talk key starts a hands-free session (≤2 h) and the next tap or Esc stops it. The tap is detected by `NotesTapDetector`, not `HotKeyProcessor`, because after a double-tap lock the processor turns the stopping press into a "release" the session would never see |
| Notes keep no audio: each ≤30 s chunk is deleted once its transcript line is committed (`.new` + fsync + rename); a chunk that fails twice goes to `failed/` and leaves a gap line | The transcript is the record (a deliberate exception to the 30-day audio rule). ## Layout and naming

Internal names still say Hex (`Hex/` target, `HexCore` package, `HexLog`, `URL.hex*`, module `Hex`). Rename only as part of the P1 package extraction, not piecemeal. User-visible strings say LegacyScribe.

- `Hex/` app (SwiftUI + TCA). Features are reducers; side effects go through dependency clients in `Hex/Clients/`.
- `HexCore/` pure logic with unit tests: hotkeys, settings, latency, formatting.
- `tools/lsbench/` headless STT benchmark: latency, peak memory, WER over fixture clips. Usage is in its `README.md`; results so far are in `docs/bench-results.md`.

## Working rules

- Log through `HexLog.<category>` with `privacy: .private` on transcript text and paths. Add a category rather than using `print`.
- Hotkey behaviour is specified in `docs/hotkey-semantics.md`; change the spec and `HotKeyProcessorTests` together.
- The rewrite step lives in `HexCore/Sources/HexCore/Rewrite/` (prompts, sanitizer, request format, fallback chain) and `Hex/Clients/RewriteClient.swift` (transport). Results are in `docs/bench-results.md`.
- Every dictation stage is stamped in `DictationTimeline` (`HexLog.latencySignposter`). New pipeline stages (LLM, context capture) get their own stamp so the menu readout stays a true key-up→paste breakdown.
- MLX code needs its Metal library: build MLX targets with `xcodebuild`, never `swift build`. Xcode 26 ships the Metal compiler separately (`xcodebuild -downloadComponent MetalToolchain`, ~700 MB, once per machine).
- Slow GitHub link: `tools/spm-shallow-mirrors.sh` fetches single commits of the large packages and writes gitignored `mirrors.json` files. Re-run it after bumping a mirrored pin; `--remove` reverts to GitHub.

## Verify

CLI builds need `-skipMacroValidation -skipPackagePluginValidation` (TCA, swift-dependencies and case-paths ship macros that Xcode otherwise asks to trust).

- `cd HexCore && swift test` runs the core unit tests.
- `xcodebuild -scheme Hex -configuration Debug -skipMacroValidation -skipPackagePluginValidation build` builds the signed `LegacyScribe Debug.app`. Signing fails with `errSecInternalComponent` when the keychain prompt for the private key can't be answered (headless sessions): add `CODE_SIGNING_ALLOWED=NO` for compile-only checks, **always with `-derivedDataPath /tmp/hex-unsigned`**. An unsigned build in the default DerivedData overwrites the signed `LegacyScribe Debug.app` with an ad hoc one, and macOS then ignores its Accessibility and Input Monitoring grants even though the toggles still show on (happened 2026-10-12; re-granting Input Monitoring was needed afterwards).
- `xcodebuild test -scheme Hex -skipMacroValidation -skipPackagePluginValidation CODE_SIGNING_ALLOWED=NO -derivedDataPath /tmp/hex-unsigned` runs the app-level TCA tests (separate DerivedData, see above).
- `tools/package-pkg.sh` builds the signed Release app and the installer package.
- `tools/notes-crashtest.py <10-min.wav> [--long <2-h.wav>] [--long-notes-feed <60-min.wav>]` runs the Notes data-safety and memory checks against the Debug build (scratch data roots; ~30 min, more with `--long`).
